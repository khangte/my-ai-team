# setup-team.sh 수정 위임

사용자가 아래 1~5번의 코드 수정을 승인했다. 이 문서에 따라 구현하고 관련 테스트를 갱신·실행한다. 현재 진행 중인 수정과 사용자 변경은 보존한다. 요청 범위 밖의 정리, 커밋, 배포는 하지 않는다.

## 1. 타이틀 워처 제거

- 세션 생존과 파인 제목을 매초 조회하는 백그라운드 타이틀 워처를 제거한다.
- 워처 전용 설명과 시작 출력도 제거한다.
- 파인 테두리와 터미널 제목은 기존 `@display_name`, 메시지 주소는 `@role`을 계속 사용한다.
- 워처 존재를 요구하는 기존 테스트는 새 동작에 맞게 갱신한다.

## 2. 기존 `.team/` 재사용

- 시작할 때 `.team/` 전체를 삭제하는 처리를 없앤다. 있으면 재사용하고, 없으면 생성한다.
- 역할별 Codex 홈과 설치 캐시는 재실행 시 보존한다.
- 생성 설정, 역할 지침, 훅은 현재 구성으로 갱신한다. 이전 실행의 역할 지침을 계속 쓰면 안 된다.
- 배정에서 빠진 스킬의 생성 링크와 플러그인 활성화는 정리하여 현재 배분표를 정확히 반영한다. 사용자가 만든 파일과 공유 캐시를 무차별 삭제하지 않는다.
- 기존 세션 종료와 새 세션 구성 순서는 재사용 경로의 쓰기 경합을 피하도록 유지한다.

## 3. Claude와 Codex의 플러그인 설치 조건 통일

다음 규칙은 양쪽 공급자에 대칭으로 적용한다.

- 실제 해당 공급자의 파인에 배정되어 활성화할 플러그인, 또는 선택 스킬의 원본으로 필요한 플러그인만 설치 대상으로 삼는다.
- 예: `developer`가 Codex이면 Claude의 `developer`에만 배정된 ponytail은 Claude에 새로 설치하지 않는다. 반대로 `developer`가 Claude이면 Codex의 `developer`에만 배정된 플러그인을 Codex에 새로 설치하지 않는다.
- 다만 해당 공급자에 로컬 설치본이 이미 있으면, 현재 역할에서 필요하지 않더라도 그 항목은 “이미 설치됨”만 출력한다. 설치·업데이트 명령은 실행하지 않는다.
- 로컬 설치본도 없고 현재 해당 공급자 역할에 필요하지 않으면 설치를 건너뛴다.
- 현재 해당 공급자 역할에 필요하고 설치본이 없을 때만 설치한다.
- 필요하지 않은 플러그인을 새로 활성화하거나 기존 설치본을 삭제하지 않는다.
- Claude 마켓플레이스 등록도 실제 새 설치나 스킬 준비에 필요한 대상으로 제한한다.
- 설치 여부를 실제 설치 명세로 판별한다. 빈 캐시 디렉터리나 다른 마켓플레이스의 동명 플러그인을 설치본으로 오인하지 않는다.
- Codex는 기본 홈과 역할별 홈이 분리되어 있다. 기본 홈에 설치되어 있다는 표시만 하고 역할 홈에는 플러그인이 없어 실제 실행에서 사용할 수 없는 상태가 되면 안 된다. 기존 역할 홈을 재사용하고, 기본 홈의 설치본을 활용할 때도 역할별 활성화·격리를 유지하면서 필요한 로컬 자산을 사용할 수 있게 한다. 이미 로컬에 있는 플러그인을 다시 내려받는 방식으로 해결하지 않는다.

## 4. 최초 로그인 후 기동 대기 개선

- Claude에서 폴더 신뢰·약관 화면뿐 아니라 준비 완료 화면도 함께 감지하여, 이미 처리된 대화상자를 각각 20초씩 기다리지 않게 한다.
- 최초 파인에서 필요한 초기 처리를 마치면 나머지는 병렬 기동한다. Claude 최초 로그인 여부 때문에 Codex까지 순차 기동하지 않게 한다.
- 필요한 대화상자 응답은 유지하고, 준비 완료를 확인한 뒤 대기와 후속 처리를 진행한다.
- 준비 확인이 시간 초과되면 성공으로 처리하지 말고 해당 파인의 실패를 보고한다. 기존 함수의 무조건 `return 0` 때문에 실패가 가려지지 않게 한다.
- Codex 로컬 훅의 `/hooks` 신뢰 처리는 실제 필요 여부를 확인하여 보존한다. 근거 없이 신뢰 절차를 제거하지 않는다.

## 5. 비활성 gstack 내용 갱신

- 주석 처리된 gstack 설치·링크 코드와 재활성화 안내를 제거한다.
- setup-team.sh의 낡은 gstack 중심 설명을 현재 플러그인·역할별 스킬 구성에 맞게 갱신한다.
- 직접 관련된 설정 파일의 비활성 gstack 블록도 함께 정리하되, 과거 판단을 기록한 문서까지 일괄 수정하지 않는다.

## 검증 및 완료 보고

- 셸 문법 검사와 관련 기존 테스트를 실행한다.
- `.team/`이 없는 최초 실행과 있는 재실행, 역할·스킬·플러그인 배분 변경 후 재실행을 검증한다.
- Claude/Codex를 바꿔 배정했을 때 불필요한 설치가 없는지, 이미 설치된 항목에서는 설치 명령을 호출하지 않는지 검증한다.
- 선택 스킬 원본용 플러그인은 활성화 역할이 비어 있어도 필요한 자산을 확보해야 한다.
- 준비 완료 화면에서는 불필요한 대기가 없고, 시간 초과는 실패로 드러나는지 확인한다. 실제 팀 세션을 임의로 종료하지 말고 모의 CLI 또는 격리된 테스트 대상을 사용한다.
- 현재 배분표와 기존 테스트의 기대값 차이를 확인하고, 의도된 현재 구성에 맞게 테스트를 갱신한다. 테스트를 통과시키기 위해 배분표를 과거 상태로 되돌리지 않는다.
- 새로 추가하거나 수정하는 함수의 선언 바로 아래에는 짧은 한국어 설명을 둔다.
- 완료 시 변경 사항, 검증 결과, 남은 제한을 사용자에게 한국어로 보고한다.
