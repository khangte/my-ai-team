# `.team/` 파일 보존 결함 수정 및 재검토 요청

사용자가 Claude에 수정 위임을 승인했다. 수정 완료 후 Codex에게 직접 전달하면 Codex가 변경 내용과 검증 결과를 리뷰한다. 기존 사용자 변경을 보존하고 커밋·푸시는 하지 않는다.

## 재현된 결함

`setup-team.sh`의 `reset_generated_team_files`는 아래 사용자 파일도 생성물로 취급하여 삭제한다.

1. `.team/dev/.agents/skills/my-skill`처럼 사용자가 직접 만든 스킬 심볼릭 링크.
2. `.team/dev/.codex/hooks.json`에 사용자가 직접 작성한 훅 파일.

기존 테스트 5개는 통과하지만, 별도 임시 디렉터리에 위 두 항목을 만든 뒤 정리 함수를 실행하면 모두 삭제된다. `.claude/skills`의 사용자 링크도 같은 삭제 조건에 걸린다.

## 수정 범위와 수용 조건

- 도구가 생성한 파일·링크와 사용자가 만든 항목을 구별하여 도구 소유 생성물만 정리한다. 소유권 기록 등 구현 방식은 간결하고 재실행에 안전하게 선택한다.
- 소유권이 불명확한 기존 파일·링크는 임의로 삭제하지 않는다. 기존 `.team/`을 처음 재사용할 때도 사용자 항목을 보존한다.
- 정리 단계만 보존하고 이후 생성 단계에서 같은 경로를 무조건 덮어쓰는 방식은 해결이 아니다. 스킬 링크 생성과 hooks.json 생성까지 실제 재실행 경로에서 사용자 항목이 보존되는지 검토한다.
- 현재 구성에서 빠진 도구 소유 스킬·훅은 계속 정리되어야 한다. 사용자 항목을 보존하려고 낡은 도구 생성물이 누적되게 하지 않는다.
- `.codex-home`, 설치 캐시, `_assets`, 기존 사용자 파일 보존과 앞서 승인된 1~5번 동작을 유지한다.
- 테스트 요청에서 확인한 실제 CLI 결과는 유지되어야 한다: Claude 기본 팀 실행 옵션의 준비 화면 감지 성공, Codex 기본 홈 캐시 링크로 스킬 28개 로드, 역할 비활성화 시 해당 플러그인 스킬 0개.
- 새 함수 또는 수정 함수의 선언 바로 아래에 짧은 한국어 설명을 둔다.

## 검증

- 사용자 작성 `.agents/skills` 및 `.claude/skills` 링크, 사용자 작성 `.codex/hooks.json`이 보존되는 회귀 테스트를 추가한다.
- 도구 생성물은 구성 변경 후 제거되고, 사용자 항목은 재실행 및 경로 충돌 시에도 덮어쓰지 않는지 검증한다.
- 메타데이터 없는 기존 `.team/`에서의 동작과 연속 두 번 이상의 재실행을 확인한다.
- 관련 기존 테스트 5개와 셸 문법·공백 검사를 실행한다. 실제 팀 세션을 종료하거나 전체 setup-team.sh를 현재 프로젝트에 실행하지 않는다.

## 완료 전달

- 완료 시 수정 파일, 변경 요지, 실행한 테스트와 결과, 남은 제한을 `bin/say`로 **ai-setup:1.1의 Codex에 직접** 전달한다. 메시지는 영어로 간결하게 쓰고 상세 근거가 길면 한국어 산출물 경로를 포함한다.
- Codex가 이 요청의 완료 결과를 기다리고 있으므로 완료 알림은 `SAY_NOWAIT=1 bin/say ai-setup:1.1 "[claude] ..."`로 즉시 보낸다. lead에 중복 보고하지 않는다.
- Codex의 리뷰가 끝나기 전에는 사용자에게 최종 완료라고 보고하지 않는다.
