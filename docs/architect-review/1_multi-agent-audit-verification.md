### G. `/clear` 강제는 캐시 파괴 — 자연 경계에서 `/compact`

세션을 짧게 유지하려고 `/clear`를 주기적으로 강제하자는 안이 있었는데, 실측하면 역효과다.

| 항목 | 값 |
|---|---|
| 세션 첫 턴 `cache_creation_input_tokens` 중앙값 | 27,547 |
| 같은 값 평균 | 27,093 |
| 148세션 누적 첫 턴 cache_create | 4.01M (전체 cache_create 42.5M의 9.4%) |
| 턴당 cache_create 평균 | 2,747 |

`/clear`는 세션을 새로 시작한다. 그러면 시스템 프롬프트·룰 체인·스킬 목록 전체가 `cache_read`에서
`cache_create`로 되돌아간다. 스킬 목록은 **세션 내에서** 캐시되지만 `/clear`가 그 캐시를 통째로 무효화한다.
cache_create 단가는 cache_read의 12.5배(1.25x vs 0.1x)이므로, 세션 재시작 한 번은 cache_read 약 344K
토큰과 같은 값이다.

프롬프트 캐시 TTL은 API 5분 / 구독 1시간이다. 그래서 한 시간 안에 연달아 세션을 열면 역할이 같은 세션끼리
공통 프리픽스 일부는 재사용된다 — 첫 턴 컨텍스트 중앙값이 47.7k인데 실제 cache_create는 27.5k에 그치는
이유가 이것이다. 그래도 매 세션 27.5k는 새로 쓴다.

`/compact`는 세션을 유지한 채 대화 본문만 요약으로 교체한다. 프리픽스(시스템 프롬프트 + 룰 체인 + 스킬 목록)는
바이트가 그대로라 계속 cache_read로 붙고, 새로 써지는 것은 요약 블록뿐이다. 컨텍스트를 줄이는 목적은 같은데
상수 오버헤드를 재구매하지 않는다.

**따라서 P1의 "200k 상한 후 분할"은 수단을 `/clear`가 아니라 `/compact`로 잡는다.** 그리고 이건 규칙으로
지시할 필요조차 없다 — `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`을 걸면 1M 컨텍스트 모델도 200K에서
자동 compaction으로 눌린다(harness 기본 동작). 실측 최장 세션이 413k까지 자란 것은 1M 창이 열려 있었기
때문이고, 이 환경변수 하나가 P1을 프롬프트 규칙 없이 강제한다.

`/compact`를 수동으로 쓸 때는 아무 때나 누르면 안 된다. 요약 시점의 본문이 새 블록이 되므로, 작업 단위가
끝나는 자연 경계(기능 구현 완료, 리뷰 반영 완료, 커밋 직후)에서만 쓴다.
